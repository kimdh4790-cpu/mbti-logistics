# /risks — 기능·변경 위험요소 분석

새 기능 추가나 코드 변경 전에 위험요소와 대비책을 먼저 정리합니다.

## 사용법
```
/risks <기능 설명 또는 변경 내용>
```

## 분석 항목

1. **기술적 위험**: 영향받는 파일·컴포넌트, 사이드이펙트, 성능
2. **보안 위험**: 인증·인가, 입력값 검증, 데이터 노출
3. **데이터 위험**: Firestore 컬렉션 구조, 기존 데이터 호환성
4. **배포 위험**: KV 업로드 순서, Worker 재시작, 캐시 퍼지
5. **되돌리기 난이도**: 롤백 가능 여부, 영향 범위

## 출력 형식
